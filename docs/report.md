## 3. 기술 과제와 해결

### 3.1 AI 챗이 "작년 여름과 비교"에 답하지 못함
- **문제**: 질문마다 최근 기록 11개 섹션을 통째로 프롬프트에 넣었습니다. 범위 밖 질문엔 답을 못 했고, 기록이 늘수록 프롬프트가 길어졌습니다.
- **결정**: 모델이 필요한 데이터를 고르는 tool-use로 전환했습니다. 읽기 전용 조회 도구 11개를 두고, 사용자 ID는 서버가 고정합니다. 자유 SQL 도구는 보안·정확성 문제로 두지 않았습니다.
- **결과**: 2026-11-14 운영 전환. 한 질문에 도구 5개를 동시에 호출하는 것을 확인했고, 답변마다 "근거: get_activities 2026-08-01~08-31"처럼 표시합니다. dev 시험에서 답변 잘림을 발견해 출력 한도를 2000에서 4096 토큰으로 올렸습니다.

### 3.2 dev 서버가 운영 DB를 같이 씀
- **문제**: 개발 컨테이너가 운영 DB에 붙어 있어 시험 데이터가 운영에 섞일 위험이 있었습니다.
- **결정**: dev 전용 `*_dev` 스키마와 운영 권한이 없는 계정을 만들고, 운영 데이터를 복사하는 스크립트를 두었습니다. 스케줄러와 알림도 dev에서는 끕니다.
- **결과**: 2026-11-13부터 분리 운영. 개발 요청함 워커가 dev에 마음 놓고 배포할 수 있는 바탕이 됐습니다.

### 3.3 "테스트한 것 = 배포되는 것"
- **문제**: 운영에서 따로 빌드하면 dev에서 확인한 것과 다른 산출물이 나갈 수 있습니다.
- **결정**: 운영은 빌드하지 않고 dev에 올라간 JAR·정적 파일을 그대로 승격합니다. 헬스체크 실패 시 직전 이미지로 자동 롤백합니다.
- **결과**: 배포 정보(환경·시각·커밋)를 첫 화면 하단에 표시해 지금 무엇이 떠 있는지 바로 확인합니다.

### 3.4 앱에서 요청하면 AI가 개발까지
- **문제**: 작은 수정도 PC 앞에서 Claude Code를 켜야 했습니다.
- **결정**: 앱의 개발 요청함에 글을 남기면, 서버 워커(systemd 상시 서비스)가 요청별 git worktree에서 Claude Code를 실행 → 커밋 → 빌드 → dev 배포합니다. 승인하면 master 병합 후 운영 반영합니다. 질문만 한 요청은 배포 없이 답변으로 끝납니다.
- **결과**: 도구 허용 목록으로 push·배포 스크립트 같은 위험한 동작은 막고, 운영 반영은 사람 승인 단계를 거칩니다.
