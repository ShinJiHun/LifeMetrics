# LifeMetrics 기획서

> 기준: 2026-11-18 · master `dd52b17` · 작성 신지훈

LifeMetrics는 한 사람의 라이딩·몸·운동·치료 기록과 커리어를 한곳에 모아, 기록을 근거로 AI가 분석하고 조언하는 개인 웹 서비스입니다. 운영 주소는 ride.tho881.me입니다.

## 1. 왜 만드는가

기록이 여러 앱에 흩어져 있어서 "지금 내 상태로 이 브레베를 완주할 수 있나" 같은 질문에 답하려면 매번 손으로 모아야 했습니다.

| 흩어진 곳 | 담긴 기록 |
| --- | --- |
| 가민 커넥트 | 라이딩 FIT, 파워·심박 |
| 따릉이 앱 | 공공자전거 이용내역 |
| 인바디·FitDays | 체성분 |
| 삼성헬스 | 식단, 걸음, 소모 칼로리 |
| 병원 서류 | 진단서, 처방전, 영수증 |
| KORA(한국 랜도너스) | 브레베·퍼머넌트 공식 기록 |

목표는 세 가지입니다.

1. **한곳에 모은다**: 파일·사진·PDF를 올리면 AI가 값을 뽑고, 사람은 검토만 한다.
2. **맥락을 알고 분석한다**: 치료 중인 부상, 그날 쓴 센서, 현재 체성분을 함께 보고 해석한다.
3. **질문하면 기록으로 답한다**: AI 챗이 필요한 기간과 데이터만 조회해서 근거와 함께 답한다.

## 2. 사용자와 공개 범위

| 사용자 | 볼 수 있는 것 |
| --- | --- |
| 본인(관리자) | 전체. 입력·수정, 의료·정산·복권 같은 민감 화면 |
| 방문자(보기 전용) | 라이딩 기록·지도, 자전거, 개발 포트폴리오, 블로그. 페르소나 챗은 하루 사용량 제한 |

민감한 화면은 프론트(RequireAdmin)와 서버 권한 검사로 이중으로 막습니다.

## 3. 구성: 네 페르소나

한 사람을 네 관점으로 나눠 기록합니다. 첫 화면에서 페르소나를 고르고, 복권은 별도 바로가기입니다.

| 페르소나 | 다루는 것 | 비중 |
| --- | --- | --- |
| 애슐리트 | 라이딩, 랜도너스, 체성분, 웨이트·유산소, 치료·검진, 장비·피팅, AI 분석·챗 | 메뉴 대부분 |
| 개발 | 이력·경력기술서·프로젝트, 경험 카드, 업무 일지, 페르소나 챗 | 포트폴리오 |
| 휴먼 | 일상 블로그, 쏘카 핸들러 운행·정산 | 일부 관리자 전용 |
| 증권 | 블로그형 공간(메뉴 미구성) | 예정 |

## 4. 기능 범위

### 애슐리트: 기록
- **라이딩**: FIT 업로드·병합, 따릉이 캡처 가져오기, 상세(지도·파워·심박·날씨·구간), 전체 경로 지도(경로·히트맵·탐험 타일), 파워 프로필
- **랜도너스**: KORA 공식 참가 기록과 GPS 라이딩 자동 연결
- **몸**: 인바디·FitDays 체성분, 감량 분석, 건강검진(PDF 추출), 치료·부상(진단서·영수증 일괄 업로드)
- **운동**: 운동 사전(GIF), 웨이트 세션·세트, 헬스장 유산소
- **장비**: 자전거·센서 등록, 부품 사용량, 피팅 데이터

### 애슐리트: 계획
- 체성분 목표(인바디 조절값 기반, W/kg), 브레베 구간 계획, 퍼머넌트 코스 160개 탐색, 라이브 라이딩(GPS 진행률)
- 예정: 투어링 계획, 장비 변경 계획

### AI
- 일일 분석(매일 새벽 배치), 활동·체성분·브레베 분석
- 애슐리트 챗: tool-use로 필요한 기록만 조회, 답변마다 근거 표시, 대화 저장
- 개발자 페르소나 챗: 경험 카드를 근거로 방문자 질문에 답변

### 운영 도구
- 개발 요청함: 앱에서 요청하면 서버 워커가 Claude Code로 작업 → dev 배포 → 승인 시 운영 반영
- 문서 뷰어(`/docs`): 이 기획서·결과서·작업 기록

## 5. 시스템 구조

```
[웹(React)] ─┐                         ┌─ MariaDB: riding_db / journal_db / lotto_db
             ├─▶ Spring Boot 백엔드 ───┤
[앱(Flutter)]┘   (GCP VM · Docker)     ├─ NAS: 업로드 원본, 코스 GPX, 운동 GIF
                  prod 8080 / dev 8081 └─ 외부: Claude API, 카카오 로그인·경로 등
```

- **배포**: `deploy.sh dev`로 개발 서버에 올린 JAR·정적 파일을 `deploy.sh prod`가 그대로 운영으로 승격합니다. 테스트한 것이 곧 배포되는 것입니다. 헬스체크에 실패하면 직전 이미지로 자동 롤백합니다.
- **환경 분리**: dev는 별도 `*_dev` 스키마와 전용 계정을 쓰고, 스케줄러·알림은 끕니다.
- **스키마 관리**: JPA 자동 생성 없이 `backend/src/main/resources/sql`의 SQL로 수동 적용합니다.

## 6. 설계 원칙

1. **업로드 → AI 추출 → 사람 검토 → 저장**. 건강검진 PDF, 진단서, 인바디 사진, 자전거 스펙 이미지에 같은 흐름을 씁니다.
2. **AI에는 고정된 조회 도구만 준다**. 자유 SQL 도구는 두지 않고, 사용자 ID는 서버가 고정합니다.
3. **코스·파일은 NAS 한 곳**. 브레베 계획과 라이브 라이딩이 같은 코스 목록을 씁니다.
4. **dev에서 확인한 산출물만 운영으로**. 운영 서버에서 직접 빌드하지 않습니다.
