# 휴먼 일기 스킬

하루 메모를 모아 밤 10시에 일기 초안을 만들고, 확인 후 휴먼 블로그에 게시하는 흐름의 Claude Code 쪽 절차다.
화면: 사이트 휴먼 페르소나 › 📔 일기 (`/human/diary`, 관리자 전용).
문체 기준: `backend/src/main/resources/diary/style-guide.md` — 일기를 직접 쓸 때는 반드시 먼저 읽는다.

## 1. "일기 메모 저장해줘" / "오늘 대화 메모로 남겨줘"

이 대화에서 오늘 있었던 일·생각·읽은 책 내용만 뽑아 메모 파일로 저장한다.

1. 날짜는 한국 시각 오늘(`TZ=Asia/Seoul date +%F`). 사용자가 "어제 거"라고 하면 그 날짜.
2. 내용: 일어난 일을 시간 순 개조식으로. 사용자의 말투와 느낌을 살리되 대화에 없는 내용은 쓰지 않는다.
   - 개발 작업 이야기는 "무엇을 만들었고 어디서 막혔고 어떻게 풀었는지"를 사람 말로 한두 줄. 코드·경로·명령어는 넣지 않는다.
   - 책 내용이 있으면 `## 책` 아래에 제목, 읽은 범위, 인상 깊은 문장, 생각.
   - 일기 문장으로 다듬지 않는다. 다듬기는 사이트 배치가 문체 가이드대로 한다.
3. 저장 위치:
   - **이 서버(GCP)에서 실행 중이면**: `/mnt/200gb/NAS/diary/inbox/<날짜>/cli-<HHMM>-<주제>.md` 에 쓴다(폴더 없으면 만든다).
     일기 화면을 열거나 초안을 만들 때 자동으로 들어간다. 업로드할 필요 없다.
   - **맥에서 실행 중이면**: `~/Desktop/depolyment/diary/<날짜>/cli-<HHMM>-<주제>.md` 에 쓰고, 올리는 방법 두 가지를 알려준다.
     - 일기 화면에서 [파일 올리기]
     - `scp -i ~/Desktop/depolyment/key/riding_key_nopass -r ~/Desktop/depolyment/diary/<날짜> jihoon@34.172.162.148:/mnt/200gb/NAS/diary/inbox/`
   - 어디서 실행 중인지 모르겠으면 `hostname` 과 `/mnt/200gb/NAS` 존재 여부로 판단한다.
4. 파일 이름은 `cli-` 로 시작해야 출처가 Claude Code 로 잡힌다(`app-` 은 Claude 앱, `manual-` 은 직접 쓴 메모).
5. 저장 후 한 줄로: 어디에 저장했는지, 메모 몇 줄인지.

## 2. "오늘 일기 써줘" (사이트 배치를 기다리지 않고 지금 초안)

사이트에서 만드는 게 원칙이다. 일기 화면의 [지금 만들기]/[다시 만들기]를 안내한다.
사용자가 대화에서 바로 보고 싶다고 하면:
1. `style-guide.md` 를 읽는다.
2. 오늘 메모(위 폴더 + 이 대화)를 근거로 가이드대로 쓴다. 지어내지 않는다.
3. 대화에 보여주기만 하고 DB 에 넣지 않는다. 게시는 사이트에서 한다.

## 3. 문체를 바꾸고 싶다고 할 때

`backend/src/main/resources/diary/style-guide.md` 만 고친다. 배치·이 스킬·Claude 앱 프로젝트 지침이 모두 이 파일을 기준으로 한다.
고친 뒤 Claude 앱 '일기' 프로젝트 지침도 바꿔야 하는지 사용자에게 한 줄로 알려준다(앱 지침은 메모 정리 방식만 담고 있어서 보통은 안 바꿔도 된다).

## 하지 말 것

- 메모·일기에 서버 IP, 키 파일, 계정, 회사 내부 시스템명·고객사명을 넣지 않는다(위 scp 안내는 사용자에게 보여주는 명령일 뿐 메모 내용이 아니다).
- 블로그(journal_post)에 직접 쓰지 않는다. 게시는 사람이 화면에서 확인하고 한다.
